# Spring Boot 图书管理系统学习项目设计

## 1. 项目目标

本项目用于通过实际开发学习 Java 后端。学习者已经掌握基本 Java 语法和面向对象概念，具有 Python、C++ 与软件开发经验，但缺少完整 Java 项目经验。

项目直接采用 Spring Boot REST API，不开发命令行版本或前端页面。接口使用 Postman 或 Apifox 调试。学习重点是 Java 工程化、Spring 分层、关系型数据库、事务、并发和测试。

## 2. 学习原则

- 采用项目驱动方式，在实现功能时学习相关 Java 与 Spring 原理。
- 核心设计和第一版业务代码由学习者手写。
- AI主要用于设计评审、原理解释、错误分析、代码审查和重复劳动。
- 不引入当前阶段没有真实需求的技术。
- 每一阶段都应留下可运行结果、测试证据和学习记录。

## 3. 第一版功能范围

### 3.1 图书管理

- 新增、修改、删除和查询图书。
- 按书名等条件搜索并分页。
- 管理总库存和可借库存。

### 3.2 读者管理

- 创建和修改读者资料。
- 查询读者当前借阅情况。

### 3.3 借阅管理

- 借书、还书和续借。
- 检查库存、重复借阅和借阅数量上限。
- 计算应还日期并判断是否逾期。
- 保证事务与并发场景中的库存一致性。

### 3.4 工程能力

- 参数校验与统一异常响应。
- 单元测试、集成测试和关键并发测试。
- API 文档、多环境配置和容器化部署。

## 4. 暂不纳入范围

- 前端页面。
- 微服务、消息队列和 Elasticsearch。
- 支付、短信和多机构管理。
- 核心借阅流程完成前的复杂认证授权、缓存和部署体系。

## 5. 技术栈

- Java 21。
- Spring Boot 3.x、Spring MVC。
- Maven。
- MySQL 8。
- MyBatis，前期不使用 MyBatis-Plus。
- Jakarta Validation。
- JUnit 5、Mockito、Spring Boot Test。
- Postman 或 Apifox。
- Git。

Lombok、OpenAPI、Spring Security、JWT、Redis、Docker 和 MapStruct 根据学习阶段逐步引入，不在项目开始时一次性加入。

## 6. 架构与职责

系统采用单体分层结构：

1. Controller 负责 HTTP 请求、参数绑定和响应。
2. Service 负责业务规则和事务边界。
3. Mapper 负责 SQL 与数据库访问。
4. MySQL 负责持久化、约束和事务支持。

主要代码包包括 `controller`、`service`、`mapper`、`entity`、`dto`、`vo`、`exception`、`config` 和 `common`。

Entity 与数据库表对应；DTO 表达接口输入；VO 表达接口输出。核心借阅规则不得放入 Controller 或 Mapper。

## 7. 核心数据流

以借书为例：

1. Controller 接收读者 ID 和图书 ID，并完成基本格式校验。
2. Service 检查读者、图书、库存、重复借阅和借阅上限。
3. Service 在同一事务内扣减可借库存并创建借阅记录。
4. Mapper 执行明确的 SQL。
5. Service 返回业务结果，Controller 转换为 HTTP 响应。

并发借阅必须使用可证明正确的数据库并发控制方式，防止可借库存变为负数或同一库存被重复借出。具体方案在事务与并发阶段通过实验比较后确定。

## 8. 错误处理

- 输入格式错误由参数校验拦截。
- 不存在的资源、库存不足、重复借阅等使用明确的业务异常和错误码。
- 使用全局异常处理器生成统一错误响应。
- 非预期错误记录必要日志，但不向调用方泄露堆栈和内部实现。

## 9. 测试策略

- Service 单元测试覆盖核心业务规则和边界条件。
- Controller 集成测试覆盖参数绑定、校验、状态码和响应体。
- 数据库集成测试验证 SQL、事务回滚和约束。
- 并发测试验证最后一册图书不会被成功借出两次。
- Postman 或 Apifox 用于探索性调试，不替代自动化测试。

## 10. 阶段路线

### 阶段 0：环境与工程启动

验证 JDK、Maven、MySQL 和 Git，创建可启动的 Spring Boot 项目，理解 Maven 结构、`pom.xml`、启动类、配置文件和一次简单 HTTP 请求。

### 阶段 1：图书 CRUD

完成 REST、依赖注入、MyBatis、基础 SQL、DTO/Entity/VO 和分页查询。

### 阶段 2：接口规范

完成参数校验、自定义异常、统一响应、日志和枚举。

### 阶段 3：读者与借阅业务

完成领域建模、时间处理、事务和业务状态流转。

### 阶段 4：事务与并发

学习隔离级别、原子更新、乐观锁、悲观锁和并发测试，解决库存竞争。

### 阶段 5：自动化测试

系统补充单元测试、集成测试、异常路径和边界测试。

### 阶段 6：安全与工程化

按需加入 Spring Security、JWT、OpenAPI、多环境配置与 Docker，并完善项目文档。

## 11. 手写与 AI 分工

学习者必须优先手写数据库建模、首个完整分层功能、核心 SQL、借还续业务、事务与库存控制、异常设计和关键测试。尤其不得直接生成并照搬 `borrowBook`、`returnBook`、`renewBook` 和并发库存处理。

AI可以直接协助 Maven 配置检查、`.gitignore`、重复 DTO/VO、普通访问器、调试数据、OpenAPI 注解、Docker 初稿和文档排版。AI还应优先采用提问、评审和解释方式协助核心模块，而不是替代学习者完成第一版。
